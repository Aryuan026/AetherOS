# 主动来信素材筛选笔记

这份笔记记录公开短信素材进入 AetherOS 前的筛选判断。它不保存原文台词，只保留结构判断和运行时边界。

## 当前结论

- BWiki 短信目录可以作为素材索引来源，但详情页大多是分支短信，不适合无脑导入。
- 公开短信的主要价值是“话题骨架”和“语言指纹”，不是直接复读原文。
- `藏好的话` 应优先读取人工复核后的种子；`此刻的话` 是即时补位；`生活照看` 与前两者并行。
- 任何公开素材进入运行时前，都要先过退场、冷却和关系阶段检查。

## 筛选层级

### ready_seed

男主先开口、内容短、无明显玩家分支依赖、离开原短信上下文也成立。

用途：

- 可转成主动来信的话题种子。
- 默认仍不逐字发送，只允许短句级人工复核后进入私有库。

### rewrite_seed

男主先开口，但原短信包含分支、长对话、关系门槛或剧情上下文。

用途：

- 只提炼“他为什么会来找 user”这个动机。
- 运行时必须重写，不能照搬原句。

### voice_only

玩家先开口、男主主要在回应，或文本更适合观察语气而不是发起话题。

用途：

- 提炼说话节奏、玩笑方式、小坚持、边界感。
- 进入角色声音核心，不作为主动来信候选。

### discard

缺少结构、上下文过强、单独使用会误导关系阶段，或不适合本应用目标。

## 当前样本观察

本地已缓存的首批详情页显示：多数短信都带有分支、关系门槛或长对话结构。即使标题和主题看起来适合主动来信，也应先归入 `rewrite_seed`，由 AI 根据当前关系、时间和记忆状态重新生成，而不是把原文搬进来。

这说明运行时接入应先支持：

- 大池子的素材候选。
- 小密度递送。
- 同主题长冷却。
- 已使用素材退场。
- `candidateId`、`sourceTitle`、`renderedHash`、`triggeredAt` 的使用记录。

## 运行时安全线

- `direct_message` 默认只接受用户私有导入或人工明确批准的短句。
- `topic_seed_rewrite` 必须附带“只取主题，不复刻原文”的生成约束。
- `language_fingerprint` 每次只注入少量，不堆成厚 prompt。
- 被判定为 `user_opens` 的素材不能用于主动开场，只能抽取回应习惯。
- 强剧情、强活动、强亲密门槛素材默认不自动触发。

## 后续采集节奏

BWiki / EdgeOne 对连续 API 请求比较敏感。缓存脚本必须慢速、可恢复，并在连续失败后立刻停止。补全素材时按角色分批，不用一次性抓完 900 多条。
