# Study Room Review

Date: 2026-07-13

## Current Shape

`书房` is currently a local study-tool surface, not a full co-reading room yet.
Its current user-visible flow is:

1. choose an assistant character;
2. import a PDF;
3. extract text from the first limited page set;
4. ask the model to generate a course outline;
5. teach chapter by chapter in character;
6. ask chapter Q&A;
7. generate a quiz for the active chapter;
8. grade the quiz locally and ask the selected character for an in-character
   review;
9. keep quiz sessions in the practice-book view;
10. send a quiz-result card back into the selected character's chat thread.

## Data And Persistence

- Courses live in IndexedDB `courses`.
- Quiz sessions live in IndexedDB `quizzes`.
- Dedicated study API settings live in localStorage key `study_api_config`.
- Tutor prompt presets live in localStorage key `study_tutor_presets`.
- Full PDF text is currently persisted inside `StudyCourse.rawText`.
- `StudyChapter.rawContentRange` is now used as the local chapter-to-source
  anchor. It is currently generated by proportional text slicing, but this
  gives future reading/chapter imports a stable field to replace.

## Current Known Limits / HOLD

- PDF is still the only import path in AetherOS `书房`.
- EPUB/TXT import, cover rendering, chapter image hydration, annotation sync,
  safe delete/archive, and durable Home-style book storage are not implemented
  here yet.
- The course outline still uses proportional text ranges; it does not yet use
  true EPUB chapters or semantic segment ids.
- `pdfjs` and `KaTeX` still load from CDN scripts at runtime, so offline/local
  package fallback is a future hardening task.
- Large app chunk warnings are not caused by this split; full code-splitting of
  heavy study dependencies can be done later.

## Co-reading Reference From AsherieSystem Mobile

AsherieSystem `apps/mobile` treats the reading tab as a two-layer co-reading
room:

- shelf: list books, show title/author/progress, refresh, import, remove;
- reader: chapter pills, current chapter content, note box, save annotation,
  submit notes to Aji, mark-read, optional read-aloud;
- structured context: reading state travels as `mobile_context.reading`, not as
  text prepended to the user-authored message;
- storage owner: Home owns the durable book library and material tools.

For AetherOS, the useful future direction is to keep `书房` as the visible
entrance, but split the implementation into a small reading library contract:

```ts
type StudyRoomMode =
  | 'study_course'
  | 'co_reading_shelf'
  | 'co_reading_reader';

type CoReadingAnchor = {
  bookId: string;
  chapterIndex: number;
  segmentId?: string;
  selectedQuote?: string;
};
```

The current `StudyCourse` can remain a study-course artifact. Co-reading should
not overwrite it; it should add a sibling book/reading model when the main plot
simulation work is ready.
